SECTION A: BASIC / INTRODUCTORY QUESTIONS
================================================================

Q1: What is DomainQA?
A: DomainQA is an AI-powered Question & Answering web application
   specifically designed for the Machine Learning domain. It uses
   Google's Gemini 2.5 Flash language model to provide expert-level
   answers to ML questions. It has four modes: Q&A, Code Generation,
   Dataset Suggestion, and Project Ideas. Users can also upload their
   own documents so that answers are grounded in their specific sources.

Q2: What problem does this project solve?
A: Machine Learning is a vast, rapidly evolving field. Students and
   researchers often waste time switching between multiple resources —
   documentation, research papers, Stack Overflow, generic AI chatbots.
   None of these tools understand your specific study material or give
   domain-specific focused answers. DomainQA solves this by combining
   ML-specialized AI with the ability to upload and reference your own
   documents, giving precise, context-aware answers in one place.

Q3: What is the main goal of this project?
A: The main goal is to build a domain-specific AI assistant that:
   1. Answers ML questions with expert-level accuracy
   2. Generates actual runnable ML code
   3. Helps find datasets for ML tasks
   4. Suggests portfolio project ideas
   5. Lets users ground answers in their own uploaded documents

Q4: Who is the target user of DomainQA?
A: Three main user groups:
   - ML Students: Get instant explanations and upload their notes/papers
   - Researchers: Query across multiple uploaded papers at once
   - ML Engineers/Practitioners: Generate and optimize ML code quickly

Q5: What makes DomainQA different from ChatGPT?
A: Several differences:
   1. Domain focus: DomainQA is tuned specifically for ML via system prompts
   2. Document grounding: Upload your own PDFs and get answers from them
   3. Specialized modes: Each tab (Q&A, Code, Datasets, Projects) has a
      different context and starter prompts optimized for that task
   4. No conversation history requirement: Each query is self-contained
      with full document context included

SECTION B: TECHNICAL QUESTIONS — ARCHITECTURE
================================================================

Q6: What is the overall architecture of DomainQA?
A: It is a full-stack web application with:
   - Frontend: Next.js (React 19 + TypeScript) running in the browser
   - Backend: Next.js API Route (route.ts) running on the server
   - AI: Google Gemini 2.5 Flash via the official SDK
   
   Flow: User submits question + files → Frontend sends POST to /api/generate
   → Server converts files to Base64, builds prompt, calls Gemini API
   → Gemini returns markdown text → Server returns JSON to frontend
   → Frontend renders the markdown as formatted HTML.

Q7: Why did you use Next.js instead of React + Express?
A: Next.js gives us both frontend and backend in one framework.
   With the App Router and API Routes, I don't need a separate
   Express server. This means:
   - One codebase, one deployment
   - No CORS configuration needed (same origin)
   - The API key stays server-side and is never exposed to the browser
   - Simpler project structure

Q8: Explain the data flow when a user asks a question.
A: 
   1. User types in the textarea in MainContent.tsx
   2. Presses Enter → handleSend() fires
   3. A FormData object is built with the prompt + any uploaded files
   4. fetch("/api/generate", { method: "POST", body: formData }) is called
   5. route.ts (server) receives the FormData
   6. Each file is converted: arrayBuffer() → Buffer → Base64 string
   7. A system prompt is constructed: "You are DomainQA, an ML Expert..."
   8. Gemini API is called with: [systemPrompt, ...base64FileObjects]
   9. Gemini returns a text response
   10. Server returns { response: text } as JSON
   11. Frontend sets response state → ReactMarkdown renders it

Q9: Why is the API call made from the server (route.ts) and not
    directly from the browser (client side)?
A: Security. The Google Gemini API requires an API key. If we called
   the API from the browser (client side), the API key would be
   embedded in the JavaScript bundle visible to anyone using
   browser DevTools. They could steal it and use my quota.
   By making the call from route.ts (which runs on the server),
   the key is in server memory only — never sent to the browser.

Q10: What is FormData and why did you use it?
A: FormData is a browser/web standard for sending multipart form data
   in HTTP requests. It can carry both text AND binary data (files).
   Regular JSON (application/json) cannot encode binary file data.
   Since we need to send both the text prompt AND PDF/file bytes
   together, FormData is the correct standard to use.

SECTION C: TECHNICAL QUESTIONS — AI / GEMINI
================================================================

Q11: What is Gemini 2.5 Flash and why did you choose it?
A: Gemini 2.5 Flash is Google DeepMind's latest large language model
   optimized for speed and efficiency (Flash = fast, lower cost vs Pro).
   I chose it because:
   - It's multimodal (processes text + files natively)
   - Very fast response times (under 3 seconds typically)
   - Large context window (can handle big uploaded documents)
   - Google's free tier allows development without payment initially
   - The @google/generative-ai SDK makes integration straightforward

Q12: What is a system prompt and how did you use it?
A: A system prompt is an instruction given to an AI model BEFORE the
   user's actual query. It sets the model's persona, behavior, and
   constraints. In DomainQA:

   "You are DomainQA, an AI-powered Machine Learning Domain Question
   & Answering System. Operate as an ML Expert, Research Assistant,
   AI Tutor, and Code Generator. Answer the following query
   concisely and accurately using markdown formatting:
   User Query: [their question]"

   This makes the model focus on ML topics and respond as an expert
   rather than a general assistant.

Q13: What is RAG? Does your project implement it?
A: RAG stands for Retrieval-Augmented Generation. It is a technique
   where, instead of relying only on the model's training data, you
   RETRIEVE relevant information from external sources and AUGMENT
   the prompt with it before generating a response.

   DomainQA implements a simplified version of RAG:
   - User uploads documents (PDFs, TXT, etc.)
   - Those documents are sent inline WITH the question to Gemini
   - Gemini reads both the question and document content together
   - The answer is grounded in the real uploaded document

   True production RAG uses vector databases (FAISS, Pinecone, Chroma)
   to store document embeddings, then semantically retrieve only the
   most relevant chunks. Our approach sends the full document inline,
   which works for small-to-medium sized files.

Q14: What is multimodal AI?
A: Multimodal AI can process multiple types of inputs — not just text,
   but also images, audio, video, and files. Gemini 2.5 Flash is
   multimodal: it can read a PDF file AND a text question in the same
   API call and generate a response that considers both inputs.
   This is how our file upload feature works — the PDF is processed
   directly by the model without any separate parsing step.

Q15: How are uploaded files sent to Gemini?
A: Files are processed like this:
   1. User picks a file → browser stores it as a File object
   2. file.arrayBuffer() reads it as raw bytes
   3. Buffer.from(bytes).toString("base64") converts to Base64 string
   4. This is wrapped as: { inlineData: { data: base64, mimeType: "application/pdf" } }
   5. This object is passed in the contents array to model.generateContent()
   Gemini accepts these inlineData parts natively as part of its API.

Q16: What is the difference between Gemini Flash and Gemini Pro?
A: 
   - Gemini Flash: Optimized for speed and cost efficiency.
     Faster responses, lower API cost, slightly less reasoning depth.
     Best for: chatbots, real-time Q&A, high-volume applications.
   
   - Gemini Pro: More powerful, deeper reasoning capability.
     Slower, more expensive. Best for: complex analysis, research tasks.
   
   For DomainQA, Flash was chosen because speed matters for UX —
   users want fast responses, and Flash handles ML questions
   accurately enough for our use case.

SECTION D: TECHNICAL QUESTIONS — FRONTEND
================================================================

Q17: What is React and why use it?
A: React is a JavaScript library for building user interfaces.
   It uses a component-based architecture — the UI is built as
   reusable, self-contained components. React uses a "Virtual DOM"
   to efficiently update only the parts of the page that change,
   making UI updates fast. We use React 19, the latest version,
   which has improved performance and concurrent rendering features.

Q18: What is TypeScript and why use it over JavaScript?
A: TypeScript is JavaScript with static type checking. You declare
   what type a variable/parameter should be, and TypeScript catches
   errors BEFORE the code runs.
   Example: interface ChatQuery { prompt: string; timestamp: Date; }
   If you accidentally pass a number as the prompt, TypeScript gives
   an error immediately. This makes large codebases much safer to
   maintain and refactor.

Q19: Explain the component structure of DomainQA.
A: The app has 6 components:
   - Header: Top navigation bar with logo and theme toggle
   - Sidebar (Left): ML topic shortcuts + document upload panel
   - MainContent (Center): The core — tabs, input, AI response display
   - RightSidebar (Right): Query history + quick stats + tips
   - ThemeProvider: Context provider for dark/light mode
   - ThemeToggle: The button that switches between dark and light

   State is managed in page.tsx (the parent) and passed down as props.

Q20: What is "lifting state up" in React?
A: It's the pattern where shared state is moved to the nearest common
   parent component. In DomainQA:
   - uploadedFiles is used by both Sidebar (to display/remove files)
     and MainContent (to send files with the API call)
   - So uploadedFiles state lives in page.tsx and is passed down
   - This way, when a file is uploaded in Sidebar, MainContent
     automatically has access to the updated file list

Q21: What is useState in React?
A: useState is a React Hook that adds state (memory) to a component.
   Syntax: const [value, setValue] = useState(initialValue);
   In DomainQA:
   - useState("qa") tracks which tab is active
   - useState("") tracks what the user typed in the textarea
   - useState(false) tracks if a request is being sent (spinner)
   - useState(null) tracks the AI response to display

Q22: What is Framer Motion and where did you use it?
A: Framer Motion is a React animation library. In DomainQA:
   1. AnimatePresence + motion.div: When switching tabs, the old
      content fades/slides out and new content fades/slides in
   2. layoutId="activeTabIndicatorMain": The blue underline indicator
      on the active tab smoothly SLIDES between tab positions when
      you switch — Framer Motion handles this automatically with
      a shared layout animation.

Q23: What is Tailwind CSS and how is it different from regular CSS?
A: Tailwind CSS is a utility-first CSS framework. Instead of writing
   custom CSS classes, you apply pre-built utility classes directly
   in your HTML/JSX. Example:
   Regular CSS: .card { display: flex; gap: 16px; border-radius: 16px; }
   Tailwind: className="flex gap-4 rounded-2xl"
   
   Benefits: No context switching between files, no naming classes,
   consistent design system, built-in responsive breakpoints (md:, xl:)
   and dark mode variants (dark:).

Q24: What is ReactMarkdown and why is it needed?
A: The Gemini API returns responses as plain text with Markdown syntax.
   For example: **bold text**, ```code blocks```, # Heading, | table |
   ReactMarkdown is a component that takes this raw Markdown string
   and renders it as proper HTML: <strong>, <code>, <h1>, <table>.
   Without it, the user would see raw asterisks and backticks instead
   of formatted content.

Q25: What is dark mode and how is it implemented?
A: Dark mode shows the app with dark backgrounds and light text,
   which reduces eye strain in low-light environments.
   Implementation in DomainQA:
   1. next-themes ThemeProvider wraps the app
   2. It adds/removes the "dark" class on the <html> element
   3. globals.css defines different CSS variable values for .dark
   4. Tailwind's dark: prefix classes apply different styles when
      the .dark class is present (e.g., dark:bg-slate-800)
   5. ThemeToggle button reads the current theme and toggles it

Q26: What is the Inter font and how is it loaded?
A: Inter is a clean, modern sans-serif font designed for screens.
   It's loaded using Next.js's built-in next/font/google system:
   const inter = Inter({ subsets: ["latin"] });
   Next.js automatically downloads the font, self-hosts it, and
   injects it — no external Google Fonts CDN call needed in production.
   This improves performance and privacy.

SECTION E: FEATURES & FUNCTIONALITY QUESTIONS
================================================================

Q27: What are the four tabs and what does each do?
A: 
   1. Q&A — Answers conceptual ML questions
      Starter prompts: "Explain attention mechanism", "What is LSTM?"
      
   2. Code Gen — Generates runnable ML code
      Starter prompts: "Fine-tune DistilBERT", "Train CNN on CIFAR-10"
      
   3. Dataset Suggestion — Recommends datasets for ML tasks
      Starter prompts: "Medical image segmentation datasets"
      
   4. Projects — Suggests portfolio project ideas
      Starter prompts: "Portfolio projects for NLP learner"
   
   Each tab has its own title, subtitle, starter prompts, and
   input placeholder — but they all share the same Gemini backend.

Q28: What is the file upload feature and how does it work?
A: The Reference Docs panel in the left sidebar lets users upload
   up to 5 files (PDF, TXT, CSV, DOCX, PPTX).
   
   Implementation:
   - A hidden <input type="file" multiple> is controlled by a ref
   - The "Upload" button clicks this hidden input programmatically
   - When files are selected, they're added to the uploadedFiles state
   - A 5-file limit is enforced with an alert
   - Files display with their name, extension, and size
   - Each file has an X button to remove it
   - When a question is sent, ALL uploaded files are included in the
     FormData and sent to Gemini along with the question

Q29: How does the query history work?
A: 
   - In page.tsx, chatHistory state is an array of ChatQuery objects
   - Each ChatQuery has: { prompt: string, timestamp: Date }
   - When the user sends a message, onSend(prompt) is called
   - This pushes a new ChatQuery to chatHistory via setChatHistory
   - page.tsx passes chatHistory as history prop to RightSidebar
   - RightSidebar shows the last 5 queries in reverse order
     (most recent first) with time formatted as HH:MM

Q30: What are starter prompts and why include them?
A: Starter prompts are pre-written example questions shown as buttons
   in the main content area. When clicked, they fill the textarea
   with that prompt, letting the user send it with one more click.
   
   Purpose:
   - Lower barrier to entry — users see what kinds of questions work
   - Guide users on how to use each mode effectively
   - Demonstrate the system's capabilities without any typing

SECTION F: CONCEPTUAL / ML THEORY QUESTIONS
================================================================

Q31: What is a Large Language Model (LLM)?
A: An LLM is a type of AI model trained on massive amounts of text
   data using a transformer architecture. It learns statistical
   patterns in language to generate human-like text responses.
   Examples: GPT-4, Gemini, Claude, LLaMA.
   "Large" refers to billions of parameters (learned weights).
   DomainQA uses Gemini 2.5 Flash as its LLM.

Q32: What is a transformer in machine learning?
A: Transformers are the neural network architecture that powers
   modern LLMs. Introduced in the 2017 paper "Attention is All
   You Need" by Vaswani et al. Key innovation:
   - Self-Attention mechanism: lets the model weigh the importance
     of each word relative to every other word in a sentence
   - Processes all tokens in parallel (unlike RNNs which are sequential)
   - Enables learning long-range dependencies in text
   DomainQA's header even says: "Transformer-powered expert answers"

Q33: What is the difference between supervised and unsupervised learning?
A: Supervised: Model is trained on labeled data (input → known output)
   Examples: Image classification (cat/dog), spam detection
   
   Unsupervised: Model finds patterns in unlabeled data (no known output)
   Examples: Clustering, dimensionality reduction, anomaly detection
   
   DomainQA can explain both when asked.

Q34: What is fine-tuning in ML?
A: Fine-tuning is taking a pre-trained model (already trained on
   large general data) and training it further on a smaller,
   domain-specific dataset. This adapts the model's capabilities
   to a specific task with much less data and compute than training
   from scratch. Example: Fine-tuning BERT on medical text for
   medical question answering.

Q35: What is a neural network?
A: A neural network is a computational model loosely inspired by
   the human brain. It consists of layers of "neurons" (mathematical
   functions). Each connection has a weight (parameter). Training
   adjusts weights using backpropagation + gradient descent to
   minimize prediction error. Deep neural networks have many hidden
   layers between input and output.

SECTION G: QUESTIONS ABOUT SPECIFIC CODE CHOICES
================================================================

Q36: Why did you use useRef for the file input?
A: The file input element is hidden (className="hidden") for styling
   reasons — the default browser file input looks ugly. We style
   our own button, and when it's clicked, we programmatically trigger
   the hidden input using fileInputRef.current?.click().
   useRef gives us a direct reference to the DOM element so we can
   call .click() on it without triggering a re-render.

Q37: Why do you check file.type || "application/pdf" for MIME type?
A: When users upload files, the browser provides a MIME type
   (e.g., "application/pdf", "text/plain"). However, some files
   may not have a MIME type recognized by the browser (especially
   on some operating systems). The fallback "application/pdf"
   ensures Gemini always gets a valid MIME type to know how to
   parse the file content.

Q38: What is suppressHydrationWarning on the html element?
A: In Next.js with dark mode, the theme class (dark/light) is applied
   to the <html> element AFTER the page renders (on the client side).
   This causes a mismatch between the server-rendered HTML and the
   client-rendered HTML — React would normally warn about this.
   suppressHydrationWarning tells React to ignore this expected
   mismatch on the html element so no warning appears in the console.

Q39: What does "use client" at the top of component files mean?
A: In Next.js App Router, components are Server Components by default
   (they render on the server). "use client" is a directive that
   marks a component as a Client Component, meaning it runs in the
   browser. Client Components are needed when using:
   - useState, useRef, useEffect (React hooks)
   - Browser APIs
   - Event handlers (onClick, onChange)
   Components like Sidebar, MainContent, RightSidebar need "use client"
   because they use hooks and event handlers.

Q40: Why is page.tsx the state container instead of a separate store?
A: For a project of this size, React's built-in useState is sufficient.
   The two shared state items (uploadedFiles and chatHistory) only need
   to be accessible by components within this single page. Using a
   state management library like Redux or Zustand would add unnecessary
   complexity. If the app grew to many pages with complex shared state,
   then a global store would be appropriate.

SECTION H: IMPROVEMENT / FUTURE SCOPE QUESTIONS
================================================================

Q41: What are the limitations of the current system?
A: 
   1. No persistent storage — history lost on page refresh
   2. Simplified RAG — sends full documents, not chunked vector search
   3. Single-session — no multi-user or authentication system
   4. No streaming — waits for full response before displaying
   5. API key hardcoded in route.ts — should be in environment variable
   6. No error retry mechanism if Gemini API fails

Q42: How would you improve this project in future versions?
A: 
   1. Vector Database RAG: Use FAISS or Pinecone to chunk documents,
      embed them, and retrieve only the most relevant sections
   2. Response Streaming: Show text word-by-word as Gemini generates it
      (using Server-Sent Events or ReadableStream API)
   3. Database persistence: Store chat history in PostgreSQL/MongoDB
   4. User authentication: Add login so each user has their own history
   5. Environment variables: Move API key to .env.local file
   6. Multi-domain: Add Finance, Legal, Medical domain modes

Q43: What is streaming and why would it improve the UX?
A: Currently, DomainQA waits for Gemini to generate the COMPLETE
   response before displaying anything (shown by the spinner).
   With streaming, text would appear word-by-word as the model
   generates it — just like how ChatGPT types out responses in
   real time. This makes the app feel much more responsive and
   reduces perceived wait time. Implemented using Gemini's
   generateContentStream() method and ReadableStream on the server.

Q44: What is a vector database and how would it improve RAG?
A: A vector database stores text as numerical vectors (embeddings)
   where semantically similar text has similar vector values.
   For RAG improvement:
   1. Split uploaded document into chunks (e.g., 512 tokens each)
   2. Convert each chunk to an embedding vector using an embedding model
   3. Store vectors in database (FAISS, Pinecone, Chroma)
   4. When user asks a question, convert question to vector
   5. Find the TOP-K most similar chunks (semantic search)
   6. Send ONLY those relevant chunks to Gemini (not the whole document)
   This scales to thousands of pages — current inline approach
   would exceed context limits with very large documents.

Q45: How would you add authentication to this project?
A: Using NextAuth.js (now Auth.js), which integrates natively with
   Next.js App Router. Would support:
   - Email/password login
   - OAuth (Google, GitHub login)
   - Session management with JWT or database sessions
   Each user would have their own chat history stored in a database
   (e.g., PostgreSQL with Prisma ORM).

SECTION I: DEPLOYMENT & PRODUCTION QUESTIONS
================================================================

Q46: How would you deploy this application?
A: The easiest deployment is on Vercel (made by the Next.js creators):
   - Push code to GitHub
   - Connect GitHub repo to Vercel
   - Vercel auto-detects Next.js and deploys
   - API Routes become serverless functions automatically
   - Environment variables (GOOGLE_API_KEY) set in Vercel dashboard
   Alternative: Docker container on AWS/GCP/Azure.

Q47: What is a serverless function?
A: A serverless function is code that runs on-demand in the cloud
   without managing a dedicated server. The cloud provider spins up
   a container, runs your function, and tears it down.
   Next.js API Routes (like route.ts) are automatically deployed
   as serverless functions on Vercel. Benefits: auto-scaling,
   pay-per-use, no server maintenance.

Q48: What environment variables should be used in production?
A: The Google API key should NEVER be hardcoded in source code
   (security risk if code is shared publicly on GitHub).
   It should be in a .env.local file:
     GOOGLE_API_KEY=AIzaSy...
   Then in route.ts:
     const apiKey = process.env.GOOGLE_API_KEY!;
   This file is gitignored and never committed to version control.
   In production (Vercel), the key is set as an environment variable
   through the hosting dashboard.
